인도 대삼각측량(Great Trigonometrical Survey)은 1802년에 시작되어 1871년에 완료된 대규모 측량 사업이며, 1856년에 에베레스트 높이가 29,002피트(약 8,840 m)로 발표되었습니다. 현재 널리 쓰이는 8,848 m 는 1954년 인도 측량에서 나온 값입니다.

02삼각측량의 원리 — 바다 건너 섬까지의 거리

전개 1 · 약 10분 · 그림 1

배도 없고 다리도 없어 바다를 건널 수 없습니다. 우리가 땅 위에서 직접 잴 수 있는 것은 두 가지뿐입니다. 해변을 따라 걸으며 재는 거리, 그리고 각도기로 재는 각도입니다.

해변에 두 지점 A, B 를 잡고 그 사이 거리를 쟀더니 100 m 였습니다. 이 선분 AB 를 측량에서는 기선(基線, base line)이라고 부릅니다. A 에서 섬을 바라본 각은 30°, B 에서 바라본 각은 60° 였습니다.

손에 들어온 숫자는 100 m, 30°, 60° 딱 세 개다. 이것만으로 섬까지 거리를 구할 수 있을까?

함께 풀기
  1. 삼각형의 세 각의 합을 이용하면 ∠C = 180° − 30° − 60° = °
  2. 따라서 삼각형 ABC 는 ∠C 가 90° 인 삼각형이고, 빗변은 이다.
  3. ∠A = 30° 이므로   AC = 100 × cos ° = 100 × = ≈ m
  4. ∠B = 60° 이므로   BC = 100 × cos ° = 100 × = m
  5. 우리는 바닷물에 발을 담그지 않았다. 물을 건넌 것은 우리가 아니라 였다.
한 걸음 더 — 기선은 왜 길어야 할까

만약 A 와 B 를 1 m 만 떨어뜨려 놓고 각을 재면 두 각이 거의 같게 나옵니다. 그러면 삼각형이 아주 홀쭉해져서 각을 0.1° 만 잘못 재도 결과가 크게 어긋납니다. 그래서 실제 측량에서는 기선을 되도록 길게 잡고, 삼각형이 정삼각형에 가까워지도록 만듭니다.

03삼각형을 이어 붙여 나라 전체를 재다

전개 2 · 약 7분 · 그림 2

우리는 이제 AC 가 약 86.6 m 라는 것을 압니다. 그러면 선분 AC 를 새로운 기선으로 쓸 수 있습니다. C 옆의 또 다른 봉우리 D 를 향해 각을 두 번 재면 D 까지의 거리가 나오고, 다시 CD 를 기선으로 삼아 E 로, E 에서 F 로 삼각형이 옆으로 번져 나갑니다. 이것을 삼각측량망이라고 합니다.

우리나라 산 정상에서 볼 수 있는 작은 돌 표석, 삼각점이 바로 이 삼각형의 꼭짓점입니다.

04GPS 는 각도가 아니라 거리를 잰다

전개 3 · 약 9분 · 그림 3

전환 질문. 여러분의 스마트폰에 각도기가 들어 있나요? 없습니다. 그런데도 지도 앱은 내 위치를 몇 m 오차로 찍어 줍니다. 어떻게 하는 걸까요?

위성 1개. "나로부터 20,100 km 떨어진 곳에 네가 있어." 이것만으로는 위성을 중심으로 하는 원 위 어딘가라는 것밖에 알 수 없습니다.

위성 2개. 원이 두 개가 되면 내 위치는 두 원 위에 동시에 있어야 합니다. 두 원의 교점은 두 개이므로, 아직 후보가 둘 남습니다.

위성 3개. 세 원이 딱 한 점에서 만납니다. 그 점이 바로 나입니다. 지도 앱의 파란 점이 찍히는 순간입니다.

이것을 삼변측량(三邊測量)이라고 합니다. 삼각측량이 세 각을 쓴다면, 삼변측량은 거리 세 개를 씁니다. 흔히 "GPS 는 삼각측량"이라고 말하지만 엄밀히는 틀린 말입니다. 그럼에도 함께 배우는 이유는 발상이 같기 때문입니다. 갈 수 없는 곳까지의 거리를 도형의 성질을 이용해 계산으로 알아낸다는 것입니다.

빈칸 채우기
  1. 위성 1개 → 내 위치의 후보는 원 위의 점 개다.
  2. 위성 2개 → 두 원의 교점이므로 후보는 개로 줄어든다.
  3. 위성 3개 → 세 원이 한 점에서 만나므로 후보는 개로 확정된다.
  4. GPS 는 각도가 아니라 를 재므로, 삼각측량이 아니라 이라고 부른다.

05거리는 어떻게 재고, 왜 위성이 4개일까

전개 4 · 약 5분 · 그림 4

줄자를 우주로 던질 수는 없습니다. 답은 시간입니다. 위성이 전파를 쏘면서 시각을 함께 실어 보내고, 스마트폰이 그 신호를 받은 시각과 비교합니다. 전파는 빛의 속도, 초속 30만 km 로 날아갑니다. 그러면 거리는 속력 × 시간 으로 구할 수 있습니다.

그런데 실제 GPS 는 위성을 최소 4개 씁니다. 첫째, 우리는 평면이 아니라 공간에 살기 때문에 가로 세로 높이 세 개의 값이 필요합니다. 둘째, 스마트폰의 시계가 정확하지 않기 때문입니다. 위성에는 원자시계가 실려 있지만 스마트폰에는 없습니다.

시계가 100만분의 1초만 틀리면 거리는 얼마나 어긋날까?

계산해 보기
  1. 거리 = ×
  2. 300,000 km/s × 0.000001 s = km = m
  3. GPS 가 모르는 값은 가로, 세로, 높이, 그리고 까지 모두 개다.
  4. 미지수의 개수만큼 식이 필요하므로 최소 개의 위성이 필요하다.

06내 위치가 정해졌다 — 그런데 그 위치를 어떻게 적을까

전개 5 · 약 8분 · 삼각비가 다시 등장하는 장면

여기서 삼각비가 돌아온다. 지금까지 GPS 이야기에는 삼각비가 직접 나오지 않았다. 그런데 위치가 정해진 다음, 그 위치를 적어 두는 순간 삼각비가 반드시 필요해진다.

GPS 가 알아낸 내 위치를 지구 중심을 원점으로 하는 직교좌표로 적으면 이렇게 됩니다.

서울  =  ( −3038, 4034, 3888 ) km

지저분한 숫자 세 개입니다. 그런데 이상한 점이 하나 있습니다. 지구 표면 위의 점이라면 x² + y² + z² = 6371² 이라는 조건을 항상 만족해야 합니다. 즉 숫자 세 개가 완전히 자유롭지 않습니다. 하나는 나머지 둘이 정해지면 따라옵니다.

그래서 실제로 필요한 숫자는 두 개뿐입니다. 이 두 개를 각도로 잡는 방법이 구면좌표계입니다.

기호이름재는 방법지리 용어로는
R동경의 길이지구 중심 O 에서 점 P 까지의 거리지구 반지름 6371 km 로 고정
θ (세타)천정각 (zenith angle)z축, 즉 북극 방향에서부터 내려오며 잰 각 (0° ~ 180°)위도 = 90° − θ
φ (파이)방위각 (azimuth)적도면 위에서 x축, 즉 본초자오선에서부터 돌며 잰 각 (0° ~ 360°)경도 = φ

이제 두 표현을 이어 봅시다. 점 P 에서 xy평면에 수선을 내려 점 P′ 를 잡으면, 직각삼각형이 두 개 생깁니다.

먼저 O, P, P′ 로 이루어진 직각삼각형에서   OP′ = R sinθ,   z = R cosθ 입니다.

다음으로 xy평면 위에서 길이 OP′ 를 x축과 y축 방향으로 나누면   x = OP′ × cosφ,   y = OP′ × sinφ 입니다.

두 식을 합치면 바로 이것이다. 지난 시간에 배운 sin 과 cos 이 그대로 들어 있다.

x = R · sinθ · cosφ

y = R · sinθ · sinφ

z = R · cosθ

빈칸 채우기
  1. 지구 표면 위의 점은 x² + y² + z² = R² 을 만족하므로, 자유롭게 정할 수 있는 값은 개다.
  2. 직각삼각형 OPP′ 에서   OP′ = R × ,   z = R ×
  3. 따라서   x = R sinθ ,   y = R sinθ ,   z = R
  4. 위도 = 90° − ,   경도 =
  5. 서울의 위도가 북위 37.6° 이므로 천정각 θ = 90° − 37.6° = °
  6. 결국 지구 위의 내 위치는 각도 개만으로 완전히 정해진다.

# ---------- 3. 위도, 경도 격자 ----------
GR = R * 1.004

def draw_parallel(lat_deg, col, rad):
    # 위도선 : theta 를 고정하고 phi 를 0~360 으로 돌린다
    t = radians(90.0 - lat_deg)
    c = curve(color=col, radius=rad)
    a = 0
    while a <= 360:
        p = radians(a)
        c.append(vec(GR*sin(t)*cos(p), GR*sin(t)*sin(p), GR*cos(t)))
        a = a + 3
    return c

def draw_meridian(lon_deg, col, rad):
    # 경도선 : phi 를 고정하고 theta 를 0~180 으로 돌린다
    p = radians(lon_deg)
    c = curve(color=col, radius=rad)
    a = 0
    while a <= 180:
        t = radians(a)
        c.append(vec(GR*sin(t)*cos(p), GR*sin(t)*sin(p), GR*cos(t)))
        a = a + 3
    return c

OP     = arrow(pos=vec(0,0,0), axis=vec(R,0,0), shaftwidth=R*0.012, color=C_P)

def new_dash(col, n):
    # 점선을 흉내내기 위해 짧은 선분 n 개를 만들어 둔다
    segs = []
    i = 0
    while i < n:
        segs.append(curve(color=col, radius=R*0.005))
        i = i + 1
    return segs

def set_dash(segs, a, b):
    n = len(segs)
    i = 0
    while i < n:
        t0 = (1.0*i) / n
        t1 = t0 + 0.62 / n
        segs[i].clear()
        segs[i].append(a + (b - a)*t0)
        segs[i].append(a + (b - a)*t1)
        i = i + 1

dash_xy = new_dash(C_AUX, 14)   # O  -> P'
dash_up = new_dash(C_AUX, 10)   # P' -> P

RT = 0.44 * R                   # 천정각 호의 반지름
RP = 0.30 * R                   # 방위각 호의 반지름
arc_th = curve(color=C_TH, radius=R*0.010)
arc_ph = curve(color=C_PH, radius=R*0.010)

    return "{:.0f}".format(v)

def f1(v):
    return "{:.1f}".format(v)

def f3(v):
    return "{:.3f}".format(v)


# ---------- 7. 화면 갱신 : 여기가 이 수업의 핵심 ----------
def update(w=None):
    th = radians(sl_th.value)      # 천정각 theta
    ph = radians(sl_ph.value)      # 방위각 phi

    st = sin(th)
    ct = cos(th)
    sp = sin(ph)
    cp = cos(ph)

    # ***** 삼각비가 그대로 등장하는 좌표 변환식 *****
    P  = vec(R*st*cp, R*st*sp, R*ct)
    Pp = vec(P.x, P.y, 0)

    Pmark.pos  = P
    Ppmark.pos = Pp
    OP.axis    = P
    lab_P.pos  = P * 1.12
    lab_Pp.pos = Pp * 1.12 + vec(0, 0, R*0.05)

    set_dash(dash_xy, vec(0,0,0), Pp)
    set_dash(dash_up, Pp, P)

    # 천정각 호 : +z 방향에서 OP 방향까지
    zhat = vec(0, 0, 1)
    u = P - zhat*dot(P, zhat)
    if mag(u) < R*0.000001:
        u = vec(1, 0, 0)
    u = norm(u)

    arc_th.clear()
    i = 0
    while i <= 48:
        t = th * (1.0*i) / 48.0
        arc_th.append(RT*(cos(t)*zhat + sin(t)*u))
        i = i + 1
    lab_th.pos = RT*1.24*(cos(th*0.5)*zhat + sin(th*0.5)*u)

    # 방위각 호 : xy평면 위에서 +x 방향부터 OP' 방향까지
    arc_ph.clear()
    i = 0
    while i <= 48:
        a = ph * (1.0*i) / 48.0
        arc_ph.append(vec(RP*cos(a), RP*sin(a), 0))
        i = i + 1
    lab_ph.pos = vec(RP*1.28*cos(ph*0.5), RP*1.28*sin(ph*0.5), R*0.04)

    # ----- 아래쪽 숫자판 -----
    dt = sl_th.value
    dp = sl_ph.value
    wt_th.text = " &nbsp; θ = " + f1(dt) + "°"
    wt_ph.text = " &nbsp; φ = " + f1(dp) + "°"

    lat = 90.0 - dt
    lon = dp
    if lon > 180.0:
        lon = lon - 360.0

    if lat >= 0:
        lat_s = "북위 " + f1(lat) + "°"
    else:
        lat_s = "남위 " + f1(-lat) + "°"

    if lon >= 0:
        lon_s = "동경 " + f1(lon) + "°"
    else:
        lon_s = "서경 " + f1(-lon) + "°"

    s = "<div style='font-size:15px;line-height:1.8'>"
    s = s + "<b>1. 직교좌표 (x, y, z)</b> = ( " + f0(P.x) + ", " + f0(P.y) + ", " + f0(P.z) + " ) km"
    s = s + " &nbsp;&rarr; 외워야 할 숫자 <b>3개</b>, 게다가 전부 지저분한 수<br>"
    s = s + "<b>2. 구면좌표 (R, θ, φ)</b> = ( 6371, " + f1(dt) + "°, " + f1(dp) + "° )"
    s = s + " &nbsp;&rarr; 지표면이면 R은 <b>항상 6371</b>, 실제로 필요한 값은 <b>2개</b><br>"
    s = s + "<b>3. 위도 · 경도</b> = " + lat_s + " , " + lon_s
    s = s + " &nbsp; <span style='color:#666'>(위도 = 90° − θ,&nbsp; 경도 = φ)</span>"
    s = s + "<hr style='border:none;border-top:1px solid #c8c8c8;margin:8px 0'>"
    s = s + "<b style='color:#b01919'>1번과 2번을 이어 주는 다리가 바로 삼각비다.</b><br>"
    s = s + "x = R · sinθ · cosφ = 6371 × " + f3(st) + " × " + f3(cp) + " = " + f0(P.x) + " km<br>"
    s = s + "y = R · sinθ · sinφ = 6371 × " + f3(st) + " × " + f3(sp) + " = " + f0(P.y) + " km<br>"
    s = s + "z = R · cosθ &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;= 6371 × " + f3(ct) + " = " + f0(P.z) + " km"
    s = s + "</div>"
    info.text = s

관찰하고 기록하기
  1. 서울 버튼을 눌렀을 때 화면 아래에 표시되는 값을 적어 보자.   θ = °,   φ = °
  2. φ 슬라이더만 움직여 보자. 이때 x 와 y 는 지만, z 는 . 그 까닭은 z = R cosθ 에 가 들어 있지 않기 때문이다.
  3. θ 를 0° 로 만들면 점 P 는 에 놓이고, 이때 φ 를 아무리 바꿔도 위치가 변하지 않는다.
  4. θ 를 90° 로 만들면 점 P 는 위를 돈다.
  5. 시드니 버튼을 누르면 θ 가 90° 보다 . 이는 남반구이기 때문이며, 위도 = 90° − θ 가 가 되어 남위로 읽힌다.
  6. 직교좌표는 지저분한 소수 3개였지만, 구면좌표는 개의 각으로 깔끔하게 적힌다.
교사용 — 시뮬레이션에서 꼭 짚어 줄 세 장면

1. φ 만 움직이기. 화면 아래 x, y 는 정신없이 바뀌는데 z 는 미동도 없습니다. 식에 φ 가 없기 때문이라는 것을 학생이 스스로 말하게 하세요.

2. 자전 버튼. φ 가 저절로 커지며 점 P 가 위도선을 따라 한 바퀴 돕니다. 위도선이 곧 θ = 일정 인 선이라는 것이 눈으로 보입니다.

3. 숫자판 아래 세 줄. 6371 × sinθ × cosφ 가 실제 숫자로 계산되어 x 가 되는 과정이 그대로 나옵니다. "삼각비가 지금 여기서 일하고 있다" 는 것을 보여 주는 장면입니다.
